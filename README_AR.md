# يومي v1.8.23 — تقرير طبي جاهز لكل زيارة

مبني على ملفات v1.8.22 الرسمية في هذه المحادثة، ويحافظ على حساب الأدوية 150 دقيقة، واستنتاج الأيام السليمة خلال المتابعة النشطة، وتحليلات البوتوكس وخط الاتجاه، والتنبيهات الحمراء.

## ما تغير

**زر «تقرير للطبيب / PDF» نفسه** في التحليل ← «التحليل التفصيلي والتقارير». لم ننشئ زرًا جديدًا، ولا قائمة جديدة في البوتوكس.

- تقرير زيارة مهيكل افتراضيًا لآخر **90 يومًا مكتملًا**، مع تغيير الفترة إلى 30/180/365 يومًا أو فترة التحليل المختارة (وتشمل التاريخ المخصص عند تحديده هناك).
- أيام الصداع والشقيقة وأيام الشقيقة وأعراض الرأس الأخرى، الأيام دون أعراض، أعلى شدة ومتوسط الشدة، عدد النوبات المرتبطة، ومدد النوبات **فقط عند وجود نهاية مسجلة 0%**.
- جرعات علاج النوبة وتصنيف الاستجابة المسجلة بعد **150 دقيقة**؛ مع توضيح أن غياب التحسن المسجل لا يثبت عدم الفعالية.
- آخر جلسة بوتوكس والتاريخ المتوقع بعد **3 أشهر تقويمية** أو تاريخ الموعد الذي أدخله المستخدم، وخلاصة أيام الصداع في فترات 30 يومًا بعد الجرعات التي توجد لها تغطية كافية.
- النوم والماء في الأيام المسجلة، وجدول موجز لآخر أيام الصداع، وأسئلة مهمة للطبيب.
- **جودة البيانات:** لا تُعدّ الأشهر التاريخية التي لا توجد فيها أي متابعة «سليمة». لا يُستنتج معدل لكل 30 يومًا قبل 28 يومًا مكتملًا وفي نصف أيامها تسجيل على الأقل؛ وتظهر الفترات الناقصة بوضوح.
- مخرجان متاحان في النافذة: «طباعة / حفظ PDF» عبر واجهة طباعة Safari، و«نسخ الملخص» نصًا.

## التثبيت

ارفع الملفات **الثلاثة فقط** `app.js` و`styles.css` و`sw.js` إلى GitHub مكان الملفات القديمة. لا تستورد JSON ولا تغير `index.html` أو `storage.js` أو `ocr.js`. أعد تشغيل تطبيق «يومي» بعد نشر الموقع وانتظار تحديث الكاش.

يُنشأ التقرير محليًا داخل التطبيق من السجلات الموجودة على جهاز المستخدم؛ إنشاء التقرير لا يرسل البيانات إلى خادم.
